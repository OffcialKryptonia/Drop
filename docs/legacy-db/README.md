# Legacy database (MySQL) reference

Used to design the Supabase Postgres schema and the import tool. None of these
files contain customer data.

| File | What it is |
|---|---|
| `legacy-schema.sql` | Exact structure of the legacy database: 62 tables, 664 columns, 133 indexes, 37 foreign keys. Generated by running all 97 Laravel migrations on a clean database. |
| `legacy-reference-data.sql` | Seeded reference data only (roles, 142 permissions, 510 default keywords, languages, 18 cancel reasons, mail templates, FAQs, app settings). The default `admin@admin.com` user is deliberately excluded. |
| `dump-live-mysql.sh` | Read-only script to dump the LIVE database for migration. Run on the old server. |

## How the schema dump was produced

Generated on MariaDB 10.11 (MySQL-compatible) from the unmodified migrations,
with one fix applied to a scratch copy only: the last migration
(`2026_04_24_174500_add_performance_indexes_to_all_main_tables`) indexes
`payments.trx_id`, but the column is `payments.txn_id`, so that migration fails
on a fresh database. The legacy repo itself is unchanged. A production database
may differ from this baseline if it was edited by hand, so the live dump remains
the source of truth for the import.

Verified: both files restore into an empty database with identical table,
column and index counts.

## Findings that shape the rewrite

- All money columns (`wallets`, `payments`, `wallet_histories`) are floating
  point `double`. The new schema uses exact `numeric(14,2)`; the import rounds
  explicitly and reconciles totals.
- `payment_gateways` stores gateway secret keys as JSON in the database. They are
  not migrated; keys are rotated and moved to Wrangler secrets.

## Dumping the live database

```bash
bash dump-live-mysql.sh <db_name> <db_user> [host] [port]
```

It asks for the password, takes a consistent snapshot, and writes
`drop-live.sql.gz`, `reconciliation.txt` and a checksum into a new
`drop-dump-<timestamp>/` folder. Never commit those files; transfer them over a
private channel.
